Methodology and source snapshots

Estimation rules (application assumptions, not SAP-approved formulas): worker pods = max(1 non-HA / 2 HA, ceil(workbook worker SAPS / assumed SAPS per pod), ceil(workbook worker memory / assumed memory per pod)). Policy pods use the same rule with 1,400 SAPS per assumed pod. Workbook policy memory, not the guide's different table, is retained. Broker has 1 pod non-HA or 3 equal CPU/memory-limit pods HA. These assumed pod counts do not establish actual replica topology.

CPU and memory demand = max(source aggregate floor, assumed worker + policy + broker + other in-cluster resources). SAPS demand = max(16,423 non-HA / 32,846 HA, workbook worker + policy + editable other-component SAPS). The other-component allowance defaults to the guide's 8,400 proxy; its composition is unresolved. Replace it with a cluster-only allowance excluding external DB/cache. It covers broker within this model, so no extra workbook broker SAPS is added. Pod slots = max(40 non-HA / 90 HA, assumed pods + other pods); the source baseline already includes Kubernetes components. Ephemeral demand = 10 GiB per assumed worker pod. Largest-pod SAPS/CPU/memory/ephemeral fit is checked separately; no bin-packing proof is attempted.

For each constraint: required surviving nodes = ceil(demand x (1 + headroom/100) / usable capacity per node). CPU/memory/SAPS usable capacity = catalog value x (1 - reserve/100); pod slots and user-provided usable ephemeral capacity are not reduced again. All constraints must fit after the selected failure. HA additionally requires at least three surviving nodes in this conservative full-replica model. Core persistent allowance = max(source floor, broker volumes + workbook policy disk), plus separate optional Prometheus/shared allowances; storage is not multiplied by headroom or survivor counts.
